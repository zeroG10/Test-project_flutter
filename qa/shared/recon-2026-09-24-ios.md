## Посилання на джобу (03)

| Спосіб | Що сталося |
|---|---|
| `ctflutter://jobs/<ключ>` (власна схема) | **нічого**: iOS читає `jobs` як хост, і апка не знаходить ключа (код `_extractKey` бере останній сегмент шляху, лише коли сегментів ≥ 2) — для тестів непридатна |
| `mobile: deepLink` з https | діалогу в дампі через 5 с не було (див. нижче — діалог «чужий номер» зникає сам) |
| **`xcrun simctl openurl booted https://…/redirect/<ключ>`** | ✅ iOS відкриває апку як universal link (`apple-app-site-association` на DEV дозволяє `/redirect/*` для dev-апки); сторінка redirect для iOS нікуди не перекидає (Play Store — лише Android) |

| Ситуація | Результат (https-посилання) |
|---|---|
| Із сесією, невідомий ключ | за 0.7 с діалог **«Link expired» / «This link is no longer valid.» / OK**; OK → Jobs list |
| Із сесією, свій номер | Jobs list; `synchronize` **нічого не додав** (на DEV без COPS) → CHK-ORDL-030 на DEV не перевірити |
| Із сесією, чужий номер | за 0.6–1.1 с діалог **«Assigned to a different phone number»** + текст + **Cancel / Log out** (як Figma 2451:82555), але **через ~0.6 с він зникає сам** — 4 спроби з 4, з автоприйняттям alert-ів і без → натиснути Cancel / Log out не вдалось |
| Без сесії, невідомий ключ | «Link expired» → OK → Welcome |
| Без сесії, чужий (незареєстрований) номер | одразу **Registration** — список не відкривається (CHK-ORDL-003) |

**Версія причини зникнення діалогу (з коду, не доведено):** у `Info.plist` немає `FlutterDeepLinkingEnabled = false`,
а у Flutter ≥ 3.27 вбудований deep linking увімкнений за замовчуванням — той самий https-шлях паралельно отримує роутер
(`go_router`), і його навігація знімає діалог, показаний поверх екрана. Діалог «Link expired» виживає, бо код спершу
сам переходить на список і лише потім його показує. Власник бачив діалог на проді вручну → **Q-ORDL-8**.

**Автоприйняття alert-ів:** `autoAcceptAlerts` (для системних запитів дозволів) може натискати кнопки Flutter-діалогів;
у тестах посилань вимикати `defaultAlertAction` на час кроку.

## Recon 6 і 6b — Check-in / Check-out (05), 2026-09-24

Скрипт `automation/mobile/scripts/recon/recon_6.py`; дерева — `recon-dumps/ios-2026-09-24/recon6_*.xml`. 7 тестових джоб
(5 + 2), усі видалено (404); локацію симулятора повернуто на адресу джоби.

| Що | Побачили | Для тестів |
|---|---|---|
| Перший Check in (дозвіл не вирішено) | через 0.9 с — системний запит; після «Allow While Using App» **за 0.3 с**: вікно апки **«Location could not be trusted» / «Your device is reporting a simulated (mock) location, so it cannot be used to verify you are on site. Turn off any mock-location app and try again.»** (Cancel / Got it); після Got it джоба лишилась **New** | **GPS-шлях на iOS-симуляторі неможливий** — апка відкидає будь-яку точку симулятора як підроблену (захист працює) |
| Локація за 5.5 км | те саме вікно за 0.2 с — до перевірки радіуса не доходить | «You are not at the job site» на симуляторі не побачити |
| Без локації (`simctl location clear`) | **те саме вікно** — і одразу, і **через 75 с** після очищення (6b): симулятор усе одно віддає свіжу точку | **ручне введення адреси** (лише коли точки немає 15 с) на симуляторі **недосяжне** |

| Кнопки за статусом | New — `Check in`; In progress — **ні Check in, ні Check out**, є `Submit deliverables`; Submitted — `Check out` | CHK-CHIO-040 — з дерева |

**Наслідок:** на iOS-симуляторі без втручання в апку недосяжні екрани підтвердження, ручне введення, перевірка радіуса і
весь запис check-in / check-out — усе, що йде після кроку «локація». Досяжні: старт потоку, системний запит, «Location
disabled» (відмова), **«Location could not be trusted» (відмова підробленій локації)**, дії за статусом. Рішення — Q-CHIO-5.
