# qa/ — QA artifacts, organised per module

One folder per product module, everything about that module inside it. A reviewer (human
or AI) opens `qa/web/<NN-module>/` and sees the analysis, the checklist, the test cases,
the open questions, the traceability and the bugs of that module — nothing else.

```
qa/
  web/                       # platform
    README.md                # module index + status
    01-authentication/       # NN-<slug>: NN = order in the SRS, slug = feature-codes.md
      authentication-analysis.md         # prompt 01: real screens vs SRS vs design
      authentication-checklist.md        # [CHK-AUTH-…] — source of truth for Sheets
      authentication-automation-plan.md  # prompt 06: reviewed copy of the candidate selection (tiers, Needs)
      authentication-test-cases.md       # TC-AUTH-… — automation candidates only
      authentication-questions.md        # open questions + answers
      authentication-rtm.md              # prompt 04: requirement → CHK → TC (human/AI owned)
      authentication-traceability.md     # CHK → test → verdict, GENERATED by trace_results.py on every run
      authentication-coverage-review.md  # prompt 05
      bugs/BUG-AUTH-001.md               # bug reports (template: qa/_templates/bug-web.md)
      exploratory/2026-09-20-login-tour.md
    02-<module>/ … NN-<module>/
  mobile/                    # same pattern, per mobile module
  api/                       # same pattern, per API module (no screen maps; steps are requests) — qa/api/README.md
  shared/                    # product-level, not module-bound
    feature-codes.md         # slug → CODE registry (the ID contract)
    checklists/              # cross-cutting: a11y, security (OWASP), performance
    oracles/                 # oracle discipline + invariants registry
    device-matrix/           # tiered device/browser matrix
    risks/ questions/        # product-level risk register and questions
  _templates/                # copy-from templates: checklist, test-cases-{web,mobile,api},
                             #   test-case-format, bug-{web,mobile}, exploratory-session
```

Rules:
- File name = `<slug>-<artifact>.md`; the slug is the row in `shared/feature-codes.md`.
  The sync script derives `--target` from the platform folder and the feature code from
  the slug, so names are load-bearing — do not rename.
- IDs never change once a checklist has been synced to Sheets or a test tagged with them.
- Every artifact names its oracle (story acceptance criterion, SRS section, Figma node, API operation, invariant, human).
- A bug is written per `prompts/08-file-bug.md` (three gates, severity walk) in the template's format.
- Sources (SRS, designs, API) stay in `docs/`; `qa/` holds only what QA produced.
