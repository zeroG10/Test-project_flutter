## Design and SRS Gaps

Design / live app has it, the SRS does not describe it:

- Email Address verification screen (3608:12035) — the SRS only describes phone verification (§3.1.1.3).
- Preferred notification channel (SMS / Email) and the SMS consent checkbox on Registration — only in CR-1 prose, not
  in the §3.1.1.2 UI description or field table.
- SMS Terms screen (3608:12130) — CR-1 FR-009 says "Accept or Decline"; the app has an Accept button and a close icon.
- Country code selector with a bottom sheet (DESIGN-AUTH-003); "Already have an account? Log in" and "Don't have an
  account yet? Sign up" links; the Login helper text and format hint.

SRS says one thing, the live app another (owner accepted the app on 2026-09-23 — the SRS is outdated here):

- D-1 Welcome header · D-2 Login by phone **or email** · D-3 button "Continue", not "Log in" · D-4 Login subtitle.
- D-5 OTP submits itself after the 4th digit (FR-OTP-05 describes a Verify tap).
- D-6 Email **required** on Registration (FR-REG-04: optional).
- D-7 / D-8 / D-10 / D-11 error texts differ from FR-REG-11, FR-LOG-03/-08, FR-REG-05.
- D-12 no format message on Login at all (FR-LOG-03 expects "Field is required.").
- D-14 names capped at 50 characters (SRS: 100) — filed as BUG-AUTH-002, resolution open (SRS or code).
- SRS §3.1.1.4 "numeric keypad" on Login no longer applies — the field accepts email.

Document quality: in the SRS the OTP and Login sections are both numbered "3.1.1.1"; the test cases cite them as
§3.1.1.3 and §3.1.1.4.

## Release Risk Summary

Release Risk: **High Risk** (by the definition above)

Reason:
- Five Critical / High rows are only partially covered: §5.2 Security, FR-008, FR-009, FR-012, FR-OTP-13.
- One High requirement is failing for one input type: FR-LOG-08 for phone numbers (BUG-AUTH-001).

  and all field validations are covered and passed on iOS (run 2). The partial rows come from the narrow-pilot scope,
  DEV constraints (fixed OTP, shared account) and the iOS simulator (no network control).

Recommendation:
- **Proceed with limitations** — the product is already accepted in production, so this is a statement about the
  regression suite, not about shipping. State the five partial rows and BUG-AUTH-001 as known limits in the report;
  close the SMS-registration path and the security path first if the scope is widened.
