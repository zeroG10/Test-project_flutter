# Profile — питання

Тут записано, де документи й застосунок розходяться. Тести перевіряють **поведінку застосунку** — так
вирішено в моделі оракула (`docs/notes/decisions.md`, 2026-09-23). Записуємо сюди, щоб розбіжність не
загубилась. Будь-який рядок власник може перевести в баг.

Статус: `відкрите` · `прийнято як є` · `баг`

Джерела:
- SRS §3.1.5 Profile (FR-PROF-01…15);
- код апки, лише читання, 2026-09-27: `profile_page.dart`, `edit_profile_page.dart`, `app_validators.dart`, `theme_cubit.dart`,
  `auth_bloc.dart`, `auth_repository_impl.dart`;
- recon 13, 2026-09-27: [recon-2026-09-24-ios.md](../../shared/recon-2026-09-24-ios.md), розділ «Recon 13».

**Збігаються з SRS:**
- картка з ім'ям, телефоном і email;
- Edit → «Edit profile» з Back і Save;
- ім'я й прізвище обов'язкові, телефон не редагується;
- Privacy Policy відкривається у вбудованому браузері;
- вихід: «Log out» / «Are you sure you want to log out?», Cancel / Log out;
- версія апки внизу.

## Питання (Q)

| # | Питання | Навіщо | Статус |
|---|---|---|---|
| Q-PRF-1 | **Редагування імені** (CHK-PRF-017, -018) зберігає зміну в **основному тестовому акаунті**. Тест змінює ім'я і перевіряє, що воно показується в апці та на сервері. Потім повертає ім'я назад через апку, а якщо тест упаде — через API (`PATCH /user/{id}`). Дозволяєш? | зміна основного акаунта | відкрите |
| Q-PRF-2 | **Видалення акаунта** (CHK-PRF-034, -035) незворотне. Пропоную робити його на **одноразовому техніку**, як у модулі 02: тест реєструє нового користувача в апці, видаляє акаунт через Edit profile → Delete і перевіряє, що той самий email більше не входить. Якщо щось лишиться — обв'язка видалить через API. Основний акаунт не чіпається. Дозволяєш? Або пропустити з коментарем? | незворотна дія на DEV | відкрите |
| Q-PRF-3 | **Вихід** (CHK-PRF-028, -029) розлогінює основний акаунт. Наступні тести входять знову (код OTP на DEV однаковий). Ок? | сесія на симуляторі | відкрите |
| Q-PRF-4 | **Офлайн-вихід** (CHK-PRF-030) — на етап Android? | на симуляторі мережу не вимкнути | відкрите |
| Q-PRF-5 | **«Усі елементи Profile в темній темі»** (CHK-PRF-023). Перевіряю темний фон за пікселями, решту — на знімку. Ок? | візуальна перевірка | відкрите |
