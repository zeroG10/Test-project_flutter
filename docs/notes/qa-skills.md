# Як запускати тести і звіти — скіли QA

> In English: [qa-skills.en.md](qa-skills.en.md)

Чотири команди для Claude Code. Пишете команду або просто кажете словами, що треба — Claude сам
обере скіл. Усі вони працюють поверх одного інструмента (`automation/mobile/scripts/qa.sh`), тому
те саме можна зробити й руками — команди наведено нижче.

| Скіл | Коли | Що скажете |
|---|---|---|
| `/qa-run` | прогнати модуль, кілька модулів або один тест | «прожени auth на android», «модуль 08 на обох» |
| `/qa-regress` | прогнати весь регрес | «регрес обох платформ», «регрес iOS» |
| `/qa-triage` | розібратися, чому тест червоний | «розбери, що впало» |
| `/qa-report` | оновити фінальні звіти і PDF | «онови звіти з останнього регресу» |

Звичайний цикл: **`/qa-regress` → (якщо є нове червоне) `/qa-triage` → `/qa-report`**.
Між ними — `/qa-run`, коли треба перевірити один модуль після виправлення.

## /qa-run — модуль або тест

- **Запуск:** `/qa-run android auth` · `/qa-run both 08,09` · `/qa-run ios tests/shared/test_splash.py::test_x`
- **Що треба сказати:** платформу (`ios`, `android` або `both` — обидві одночасно) і що запускати
  (номер модуля, назву або її частину). Платформу не вказали — Claude спитає, сам не вгадує.
- **Що робить:** показує план → перевіряє, що зміни закомічені → сам піднімає симулятор /
  емулятор і Appium → запускає → порівнює з останнім фінальним прогоном.
- **Що отримаєте:** скільки пройшло / впало / не запустилось і головне — що з цього **нове**
  (нове червоне, нове «не запустилось»), а що — відомі баги.
- **Чого не робить:** не чіпає звіти, трасування, баги; не перезапускає червоний тест «до зеленого».

## /qa-regress — весь регрес

- **Запуск:** `/qa-regress both` · `/qa-regress android` · `/qa-regress ios`
- **Час:** iOS ≈ 1,5 год, Android ≈ 2 год 45 хв, обидві одночасно ≈ 2 год 45 хв. Mac — на зарядці,
  кришка відкрита.
- **Що робить:** те саме, що `/qa-run`, але для всього набору, з відео для впалих тестів, і
  порівнює **кожен тест** з останнім фінальним прогоном.
- **Що отримаєте:** або «прогін повторює попередній» з цифрами, або список відмінностей: нове
  червоне, нове «не запустилось», тести, що зникли, і «схоже, виправлено» (був червоний через
  баг, тепер зелений).
- **Наприкінці спитає:** розібрати нове червоне (`/qa-triage`)? зробити цей прогін основою
  звітів (`/qa-report`)? вимкнути пристрої?
- Можна попросити кілька прогонів поспіль («три рази») — для перевірки повторюваності.

## /qa-triage — чому червоне

- **Запуск:** `/qa-triage` (останній прогін) або «розбери, чому впав TC-AUTH-007 на iOS».
- **Що робить:** для кожного нового червоного дивиться докази (крок, знімок екрана, відео,
  відповіді сервера), код тесту і вимогу, проти якої тест перевіряє. І вирішує одне з п'яти:

  | Причина | Що далі |
  |---|---|
  | середовище (пристрій, мережа, сервер, навантаження) | «не запустилось» з причиною; тест лишається в боргу |
  | сам тест | пропозиція виправити тест — робиться за вашим словом |
  | неправильне очікування в тесті | виправляється тест-кейс і тест за вимогою; бага немає |
  | застосунок | чернетка бага з доказами; заводиться лише за вашим словом |
  | ніде не написано, як має бути | питання до вас; перевірка не рахується пройденою |

- **Єдиний дозволений перезапуск:** один раз, один тест, окремо — лише щоб відрізнити «середовище»
  від решти. Обидва результати показуються.
- **Що отримаєте:** таблицю — тест, що сталося простими словами, рішення, доказ, пропозиція — і
  окремим блоком питання, на які можете відповісти лише ви.

## /qa-report — звіти

- **Запуск:** `/qa-report` — після повного регресу.
- **Що робить:** питає, які прогони брати → перевіряє, що це повний чистий регрес → оновлює
  трасування → перезбирає 6 звітів (iOS / Android / спільний × внутрішній / клієнтський) і 6 PDF →
  перевіряє, що у копії для поширення не лишилось даних тестових акаунтів (має бути 0 · 0 · 0).
- **Що отримаєте:** цифри по кожному звіту, що змінилося проти попередніх, відкриті локальні сторінки.
- **Лише за вашим словом:** оновити опубліковані сторінки («опублікуй»), «коміть», «пуш».
  Клієнтський звіт ви погоджуєте перед відправкою.

## Правила, які діють у всіх скілах

1. Запуск скіла — це ваша команда на цей один прогін. Нічого іншого без вас не запускається.
2. Перед прогоном зміни мають бути закомічені; коміт — лише на «коміть», пуш — на «пуш».
3. Червоний тест не перезапускають, поки не позеленіє. Спершу — причина.
4. «Не запустилось» ніколи не рахується як «пройшло».
5. Баги заводяться, а звіти публікуються лише за вашим словом.
6. iOS і Android одночасно — можна (у кожної свій акаунт і свій Appium); два прогони однієї
   платформи одночасно — ні. Деталі: `automation/mobile/PARALLEL-RUNS.md`.

## Те саме руками

```bash
cd automation/mobile
scripts/qa.sh both all                  # регрес обох платформ одночасно
scripts/qa.sh android auth              # модуль
scripts/qa.sh both all --dry-run        # лише план

cd ../tools
uv run python compare_runs.py --platform android ../mobile/results/android/<прогін>   # що змінилося
uv run python build_reports.py --share && node export_pdf.mjs                         # звіти і PDF
```
