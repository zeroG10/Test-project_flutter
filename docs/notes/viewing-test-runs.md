# Як дивитися прогони тестів (веб)

Пам'ятка для QA-власника проєкту: як запустити перевірки і де подивитися, що саме
відбувалося. Усі команди виконуються з кореня репозиторію.

## Швидкий старт

```bash
npm run pw:test        # прогнати всі тести
npm run pw:report      # відкрити HTML-звіт останнього прогону в браузері
```

Звіт відкривається на `http://localhost:9323`. Закривається `Ctrl+C` у терміналі.

## Чотири способи подивитися

| Спосіб | Команда | Що бачиш | Коли зручно |
|---|---|---|---|
| Лог у терміналі | `npm run pw:test` | рядок на кожен тест: `✓` пройшов, `✘` впав, `-` пропущено, і підсумок | завжди, це відбувається саме по собі |
| **HTML-звіт** | `npm run pw:report` | список тестів, кроки з таймінгами, скріншот, відео і трейс для падінь | **основний спосіб**, після будь-якого прогону |
| Живий браузер | `npm run pw:test -- --headed` | справжнє вікно браузера, видно кліки і введення тексту | демонстрація; повільніше за звичайний прогін |
| Інтерактивний режим | `npm run pw:ui` | дерево тестів, запуск окремого тесту, перемотування кроків | коли хочеш сам поклікати без участі AI |

## Що всередині HTML-звіту

Зліва список тестів, згрупований за файлами і браузерами. Зелене пройшло, червоне впало.
Клік на тест відкриває його кроки: кожен рядок це дія або перевірка з часом виконання.

Для тесту, що впав, додається:

- **Скріншот** сторінки в момент падіння;
- **Відео** всього тесту;
- **Trace** — покрокове перемотування. Клік на крок показує, як виглядала сторінка саме
  тоді, які були запити до сервера і що писала консоль. Це найсильніший інструмент розбору:
  видно не лише що впало, а й чому;
- **Error context** — текстовий знімок сторінки для швидкого читання.

Перевірка мап екранів (`npm run pw:map-health`) додає до звіту таблицю по кожному екрану:
які елементи знайшлися, які зникли, які стали неоднозначними.

## Де що лежить

| Що | Шлях |
|---|---|
| HTML-звіт | `automation/web/playwright/playwright-report/index.html` |
| Скріншоти, відео, трейси | `automation/web/playwright/test-results/` |
| Машинний результат прогону | `automation/web/playwright/test-results/results.json` |

Усе це в `.gitignore`: артефакти не комітяться, бо вони перестворюються кожним прогоном.
Окремий трейс можна відкрити напряму:

```bash
npx playwright show-trace automation/web/playwright/test-results/<тека-тесту>/trace.zip
```

## Корисні варіанти запуску

```bash
npm run pw:test -- --project=chromium-public   # тільки публічні сторінки, без логіну
npm run pw:test -- --grep @CHK-AUTH            # тільки перевірки модуля авторизації
npm run pw:test -- tests/authentication        # тільки один модуль
npm run pw:smoke                               # димові перевірки, найшвидше
npm run pw:map-health                          # чи не зламалися локатори після змін на сайті
```

## Нюанс: відомі баги

Тест, позначений як відомий баг (`test.fail()`), падає навмисно. Playwright рахує це
очікуваним, тому прогін лишається зеленим, а **скріншот, відео і трейс для такого тесту не
зберігаються** — лишається тільки текстовий `error-context.md`. Якщо для звіту потрібні
докази саме з прогону, запусти з примусовим збереженням:

```bash
npm run pw:test -- --grep @BUG-<КОД>-NNN --trace on --video on
```

Постійні докази по кожному багу лежать окремо і комітяться:
`qa/web/<модуль>/bugs/evidence/BUG-<КОД>-NNN/`.

## Звіт по модулю

Крім HTML-звіту, на кожен модуль є текстовий підсумок покриття:
`qa/web/<модуль>/<модуль>-traceability.md`. Там таблиця «пункт чекліста → тест → вердикт»
і підсумковий рядок: скільки пройшло, впало, заблоковано і скільки ще не покрито.
Файл перегенеровується після прогону:

```bash
cd automation/tools && uv run python trace_results.py \
  --platform web \
  --checklist ../../qa/web/<модуль>/<модуль>-checklist.md \
  --playwright-json ../web/playwright/test-results/results.json \
  --out ../../qa/web/<модуль>/<модуль>-traceability.md
```

## Якщо звіт виглядає дивно

- **Звіт показує менше тестів, ніж очікувалося.** Кожен прогін перезаписує звіт. Якщо
  останній запуск був із фільтром (`--grep`, шлях до файлу), у звіті будуть тільки ці тести.
  Прогони `npm run pw:test` без фільтра, щоб побачити повну картину.
- **Немає `results.json`.** Так буває, якщо прогін запустили з власним репортером
  (`--reporter=line`). Це вимикає репортери з конфігурації. Запускай без цього прапорця.
- **Тести довго стартують.** DEV віддає бандл на 3.7 МБ, перше відкриття сторінки займає
  до півхвилини. Тому прогін іде в один потік, це навмисно.
