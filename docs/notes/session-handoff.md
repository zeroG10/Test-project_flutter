## 7. Контекст із розмови, якого немає в інших файлах

### 7.1 Стратегія демо і звіту (погоджено з власником)

- **Аудиторія демо:** технічні люди + ПМ. Звіт — два рівні в одному документі: зверху півсторінки
  для ПМ (скільки покрито, скільки часу економить проти ручної регресії, які ризики знайдено), нижче
  технічна частина (матриця трасування, Allure, контекст прогону, що свідомо не автоматизовано і чому).
- **Що переконує (не «100% зелене» — воно насторожує):** доведений червоний для кожного тесту;
  трасування `FR-xxx → CHK → TC → тест → вердикт` (у SRS 154 вимоги з кодами); чесні `Blocked`
  з причиною; контекст прогону (білд, пристрій, ОС, дата); повторюваність — 3 стабільні прогони
  поспіль (історія Allure); знахідки процесу (CR-2 без покриття в чеклісті, 31 перевірка без статусу,
  темна тема — 3 перевірки на весь застосунок, розбіжності D-1…D-5, захист локації, пастка хибного
  Passed на OTP); цифра для ПМ — час ручної регресії 625 перевірок × конфігурації проти автопрогону.
- **Цифри скоупу:** 625 перевірок; breadth-suite закриває ~284 унікальні (45%): переходи 111,
  «елемент відображається» 128, успішні сценарії 113. Груба класифікація всього чеклісту: навігація
  і дії 237, валідація 105, стан/дані 40, візуал 45, інше 198.
- **Архітектура набору (4 рівні):** досяжність кожного екрана (~15–18) → переходи між екранами +
  назад (~20–25) → наскрізний happy flow логін→список→джоба→check-in→опитування→фотозвіт→нотатка→
  здача→check-out (3–5 довгих) → ключові валідації (~10). Разом 55–65. Тести з маркером `shared`
  ганяються на обох платформах без переписування.
- **Політика доказів:** скріншот + page source на падінні — вже вшито в `conftest.py`; іменовані
  скріншоти на ключових моментах happy flow і відеозапис наскрізного сценарію — **ще треба додати**
  в харнес перед написанням тестів. Не знімати все підряд.
- **Логін:** один раз на прогін, далі тести в відкритій сесії (`noReset`) — через FR-OTP-13
  (блок акаунта на 2 хв після надлишку спроб) і таймер повторної відправки. Перевірки самого входу —
  окремий набір із чистого стану. Альтернатива для тестів, яким логін не цікавий: токен через API
  (`POST /auth/sign-in/phone|email` + OTP) — не перевірено, чи можна підкласти токен у апку.
- **Скоуп-рішення:** планшети поза демо; темна тема — лише перемикач (3 перевірки); 31 перевірка без
  статусу — Skipped; система COPS (онбординг, SMS-згода FR-001…007) — поза межами; мінімальні ОС —
  не проганяємо. Усе з причинами в `decisions.md`.
- **Нові перевірки CR-2** пишуться з PRD і приносяться власнику на валідацію до автоматизації:
  додати екземпляр (Add Room), редагувати без дубля, видалити з підтвердженням, автонумерація без
  ручного перейменування, незаповнений екземпляр блокує відправку, чернетка/офлайн, фото прив'язані
  до екземпляра. На DEV є 7 опублікованих опитувань з префіксом `Repeatable` (`docs/api/dev-test-data.md`).
  На картках секцій у коді є `ValueKey('section-card-…')`, але нативні драйвери їх не бачать.

### 7.3 Пастки інструментів (щоб не наступати вдруге)

- zsh: у `git show $R:lib/...` конструкція `$R:l` — модифікатор zsh. Писати `"${R}:lib/..."`.
- mobile MCP потребує агента в симуляторі: `mobilecli agent install --device <UDID>` (бінарник у
  `~/.npm/_npx/.../mobilecli-darwin-arm64`). Дерево MCP менш точне за Appium — карти будувати з Appium.
- Appium-сесія з `app`-капабіліті перевстановлює апку → холодний старт + системний запит сповіщень.
  Для знімання поточного екрана без перезапуску — `scripts/recon/dump_screen.py` (noReset,
  forceAppLaunch=false).
- Налаштування апки на симуляторі: `<data-container>/Library/Preferences/com.concerttechnologies.app.dev.plist`,
  ключі з префіксом `flutter.`; писати через `xcrun simctl spawn booted defaults write <шлях-без-.plist> …`
  при закритій апці.
- Галерея не відкривається, якщо в Photos симулятора немає фото → `xcrun simctl addmedia booted <jpg>`
  (є `automation/mobile/fixtures/media/site_photo.jpg`).
- На Welcome/Login після дотику до поля клавіатура зсуває макет — координати з попереднього знімка
  стають неактуальними; у тестах — лише локатори, не координати.
- Фонові команди (збірка ~2–5 хв, `fvm install` > 10 хв) запускати з `run_in_background`.
