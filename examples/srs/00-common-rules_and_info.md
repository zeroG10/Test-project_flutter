1. Introduction 
1.1 Purpose  
This document defines the software requirements for the Acme Field Services Admin Panel, a web-based application used to manage users, surveys, templates, photo metadata, and survey responses generated by the Acme Field Services Mobile Application.
The Admin Panel serves as the central administrative and configuration system supporting the Field Services workflow.
1.2 Intended Audience and Reading Suggestions 
This document is intended for all the project stakeholders, the project management team, and the development team, including frontend developers and quality assurance engineers.

1.4 Product Scope 
The Admin Panel is a React-based web application with a Node.js backend, tightly integrated with the Acme Field Services Mobile Application.

Its primary responsibilities include:
	•	Managing Mobile App users (Field Technicians and Managers);
	•	Creating and maintaining Surveys and Survey Templates;
	•	Managing Photo Tags used in mobile Photo Reports;
	•	Reviewing Survey Responses submitted by Field Technicians;
	•	Enforcing role-based access control and permissions.

The Admin Panel does not replace operational systems (job assignment, scheduling) but complements them.

2. Overall Description 
2.1 Product Perspective 
The Admin Panel is a standalone web application that:
	•	Shares authentication and data with the Mobile App backend;
	•	Exposes configuration and review tools unavailable in the mobile app;
	•	Acts as the source of truth for surveys and templates.

2.5 Design and Implementation Constraints 
The development of the administrator panel web application is dedicated only to the web; the design will be responsive. 
The minimal resolution width will be 1366px, and the maximum resolution will be 3840px.
The maximum viewport width will be 2100px.
The designs of the administration panel module are based on the components provided by Ant design style guides (check the reference). 
Additionally, custom UI components will be designed and implemented by request. 



Users with disabilities (colorblindness) should be considered. The design of the application will respond to special color settings in the browser.

User scale factored from 75% to 150% by default font size.

The source design file of the administrator application will be stored in a Figma .fig file. This file will contain:
1. Design components
2. Web application design

2.6 Assumptions, Dependencies, and Risks
Assumption:
A1: Project Facilitators (PFs) utilize the existing Acme Field Services system for job assignment and management.
A2: Project Facilitators (PFs) may utilize the Admin Panel as both root-users and Managers to manage all available data
A3: Admin Panel users are trained internal staff
A4: No offline mode required for Admin Panel
Dependencies:
D1: Backend API Availability: Backend APIs must be available to support essential functions, including user authentication, job data retrieval, and document storage from both, internal and external APIs
D2: Data Management System: The mobile application relies on data managed via a Acme Field Services Admin web application. This requires dynamic data retrieval from a backend server connected to the DB content.
D3: Frontend Framework: A suitable frontend framework or library (e.g., React) is required to build the web application. All necessary updates and modifications to this library must be applied to the application.
Risk Factors
R1: Design Changes: Alterations to the design of the actual products may necessitate significant application updates and require re-submission to mobile marketplaces (App Store, Google Play).
R2: Data Flexibility: Dependence on hardcoded data would limit the application's flexibility and demand manual updates whenever data changes occur.
